# 人生模拟器 · Life Simulator

> 一款纯前端、零依赖的浏览器文字向人生模拟游戏：从呱呱坠地走到寿终正寝，
> 每一次行动与抉择都会沿因果链沉淀为故事，并在结算页复盘为一张人生全景图。

| 项目 | 说明 |
|------|------|
| 版本 | **v2.4.0** |
| 定位 | 单一主角人生模拟（不是家族/子女模拟器） |
| 技术栈 | 原生 HTML + CSS + JavaScript（无构建、无包管理、无第三方库） |
| 运行方式 | 双击 `index.html` 即可（`file://` 直接运行） |
| 测试 | `node tests/run.js`，**246 个用例**（零依赖自研测试框架，含无头性能基准） |
| 协议 | MIT |

## 一、项目简介

玩家扮演**唯一主角**，从 1990 年前后的出生开始，在真实公历纪年中经历
入园、升学、高考、就业、婚育、置业、投资、养老、离世。

核心特色：

- **真实纪年与时代事件**：时钟从 1990 起按真实公历推进（含闰年），下海、入世、非典、
  奥运、智能机、股灾、房价、疫情、AI 等时代事件按年份窗口触发。
- **大五人格 + 心理状态**：出生即定 OCEAN 气质底色，且可被行动缓慢塑造（封顶 ±15、每年向本性回弹）；
  压力 / 抑郁 / 创伤独立建模，与行动、疾病、财务、关系双向耦合。
- **因果链叙事**：抉择与行动可埋下伏笔种子（seeds），若干月后触发延时回响（timers），
  并被后续事件按 `requiresSeed` / `consumesSeed` 回收，形成跨十年的因果链。
- **资产与金融**：房产、车辆可全款/按揭购入，房贷按月扣款、车辆逐年折旧；
  A 股与虚拟币行情随年随机游走（含崩盘），可按现价买卖结算真实盈亏。
- **故事积分与特殊结局**：五维（雄心/善心/冒险/智识/活力）随行为累积，
  6 条故事线记录"开了哪些线、推进到哪"，结算页绘制雷达图并给出 8 类结局之一。
- **习惯养成闭环（v1.3.0）**：🌱 从习惯面板"立一个习惯"（锻炼/阅读/冥想/写作/储蓄/社交/志愿/做饭），
  每月坚持累加 streak，达到阈值即"内化"——一次性获得性格漂移与属性增益，把"性格可塑"从被动变主动；
  放弃只断连击、不惩罚。完全活在独立的 `s.habit` 子树里，不干扰任何其它系统。
- **未竟之事 · 人生留白（v1.3.0）**：🕯️ 生命尽头，结算页温柔列出"这辈子从没走过的路"
  （从未恋爱成家 / 从未生育 / 从未置业 / 从未远行 / 从未孤注一掷），只读评估、不改写任何状态，
  制造回味与重开动机。
- **暖事件 · 小确幸（v1.3.0）**：一批轻量正面微事件（邻居送菜、旧友重逢、孩子第一次叫你、
  雨后初晴、流浪猫蹭你、帮了陌生人…）按心情与季节加权进入抉择池，平衡原本偏负面的情绪曲线。
- **负债催收链（v1.4.0）**：💳 财产转负后，催款会逐级升级——逾期提醒 → 催收来电 → 上门追债 → 法院传票，
  玩家每次都面临"滚雪球还是止血"的抉择；另有协商债务重组（止血出口）与"最后一笔"（还清收尾）。
  同时负债压力按深度分级：欠得越深，心情/免疫/心理压力每年被扣得越狠。
- **消费模式（v1.5.0）**：🛍️ 把财富变成"能兑换的生活体验"。按财富分层解锁——
  **温饱 → 小康 → 富足 → 奢华**，钱越多能解锁的档次越高。三块结构：
  **耐用品**（买入后持有数年、持续给属性加成、到期折旧退役）、
  **一次性消费**（火锅/演唱会/米其林/海上派对，即时兑换好心情）、
  **服务业订阅**（私教/家政/私人医生/管家，每月扣月费持续享受，欠费自动停订）。
  独立面板 `consumePanel.js`，并为「生活品质」新增评分维度与 8 枚消费成就。
- **玩法层（v1.6.0）**：🎮 四项**彼此独立**的玩法增强，各自一个文件 / 配置节 / state 子树 / 测试：
  - **📜 人生合约**：每 5 年一期自动下发 3 张候选，玩家**主动认领 1 张**，到期验收。
    达标给单项奖励（属性 / 现金 / 徽章），**违约不扣分**、只写一条日志——"人生不惩罚你，只是错过"。
  - **🏷️ 倾向标签**：死亡结算时按**各自的使用量 / 风格**打上几枚身份标签（逆天改命 / 富甲一方 /
    八面玲珑 / 凭自己 / 行善者 / 生活家…），补上"我这一局是什么人"的认知。
  - **🔓 元进度解锁**：把通关数 / 成就数 / 结局沉淀进独立 `localStorage`，用来**分别解锁**三个金手指
    （神壕默认可用；海克斯需通关 1 局；数据化需 15 成就或 3 结局），补上跨周目动机。
    **默认 soft**：只标注"尚未解锁"、不强制关闭；可开 `hardLock` 收紧。
  - **⚡ 月行动点 AP**：给每月一份行动预算，让"这个月先做什么"成为选择。因涉及全局行动项，
    **默认关闭**；开启后默认 soft（只提示计数、不阻断），可切 hard（耗尽即拦）。
- **金手指三模块（v1.2.0，默认全关）**：🧬 海克斯（算力 HE · 改写规则）、
  💰 神壕（现金 + 月额度 · 钞能力）、📊 人数数据化（观测点 DP + 人情 · 把关系变成数据）。
  三者**彼此独立**：各占一个文件、一份配置、一棵 state 子树、一种资源、一组存档字段、
  一个 UI 面板、一个测试文件；删掉或关掉任意一个，其余两个的行为完全不变。
- **工程化红线**：无外部依赖、`file://` 可运行、脚本顺序受测试保护。

## 二、快速开始

### 方式一：双击运行（推荐，零依赖）

直接双击 `game/index.html`，浏览器以 `file://` 协议打开即可开始游戏。
此方式下所有存档（`localStorage`）与音效均可正常工作；仅 Service Worker 离线缓存与
"安装到桌面"不可用（浏览器安全策略限制，属预期行为，页面会静默降级）。

### 方式二：本地静态服务器

在 `game` 目录下任选一种：

```bash
# Python 3
python -m http.server 8000

# Node.js（无额外依赖）
npx serve .
```

随后访问 `http://localhost:8000/index.html`。此方式下 `sw.js` 会注册成功，
首次访问后可离线游玩。

### 方式三：安装为 PWA

通过 `http(s)://` 部署（或上文的本地服务器方式）访问后，满足浏览器安装条件时，
顶栏会出现"安装"按钮，可安装到桌面 / 手机主屏，全屏运行。

### 运行测试

```bash
node tests/run.js
```

无需 `npm install`，测试框架为零依赖自研实现。

## 四、架构说明

### 4.1 分层设计

```text
┌──────────────────────────── 表现层 ────────────────────────────┐
│ ui/hud.js（~20fps 渲染全部卡片与结算页）  ui/pwa.js  css/style.css │
└──────────────────────────────────────────────────────────────┘
                             ↑ 只读 state / 订阅事件
┌──────────────────────────── 业务层 ────────────────────────────┐
│ systems/*.js —— 31 个注册系统 + era / scenario / save 服务模块    │
│ 每个系统：IIFE 包裹 → Game.systems.create(name, priority) → on(...) │
└──────────────────────────────────────────────────────────────┘
                             ↑ 只通过事件总线通信
┌──────────────────────────── 框架层 ────────────────────────────┐
│ core/ns.js  core/bus.js  core/util.js  core/state.js             │
│ core/system.js（注册表）  core/loop.js（主循环）                  │
└──────────────────────────────────────────────────────────────┘
                             ↑ 纯数据
┌──────────────────────────── 配置层 ────────────────────────────┐
│ config.js —— 天气谱 / 疾病库 / 升学链 / 职业 / 婚恋 / 抉择 / 行动 /  │
│ 资产 / 投资 / 故事 / 成就 / 音效 … 全部数值与文案的唯一来源        │
└──────────────────────────────────────────────────────────────┘
```

约束：**逻辑写系统、数值写 config、表现写 hud/css**；系统之间只通过事件总线通信，
不互相直接调用（`Game.state` 与 `Game.util` 为共享只读/工具入口）。

### 4.2 主循环与时间推进

`core/loop.js` 采用 `requestAnimationFrame` + 时间累加器：

- 支持**暂停 / 继续 / 单步 / 多档速度**；
- 累加器满一格即执行一次 `step()`，按月推进：`day → month → season → year`；
- **`pendingDecision` 存在时冻结推进**（抉择弹窗期间时间停止，玩家思考不消耗人生）；
- 主角死亡后 `step()` 不再推进时间。

### 4.3 系统注册表与优先级

`core/system.js` 的 `create(name, priority)` 即声明式登记，按 `priority` 升序执行，
保证"先算基础状态、后算衍生结果"。当前注册顺序：

| Priority | 系统 | 职责 / 依赖 |
|---------:|------|------------|
| **5** | **meta 🔓** | 元进度解锁：最先跑，按跨周目数据决定"哪些金手指可用"（独立模块，v1.6.0） |
| **8** | **hex 🧪** | 🧬 海克斯：算力 HE + 规则类外挂，向 lifespan / decisions / actions 提供钩子 |

## 五、金手指三模块（🧬 / 💰 / 📊）

> v1.2.0 新增。一句话：**三扇各走各的门，默认全关，彼此之间没有关系。**

### 5.1 设计红线

1. **互不依赖**：没有共享底座、共享货币、共享开关、共享效果通道。
   各自：独立文件 · 独立 `config` 节 · 独立 state 子树 · 独立资源 · 独立存档字段 ·
   独立 UI 面板 · 独立测试文件。任一块缺失 / 关闭，其余两块行为完全不变。
2. **默认全关**：每个模块都要显式开启（`config.*.enabled = false`），开局不带任何挂。
3. **不改引擎**：效果一律走既有的 `Game.state.applyEffects()`；对引擎的侵入只落在
   **显式钩子**上，且一律加守卫：`Game.hex && Game.hex.onDeath(...)`。
4. **各有各的代价**：氪命换算力 / 月额度与边际递减 / 观测点与人情——代价规则归各模块自己，
   不合并计算。

### 5.2 三本账

| 模块 | 自己的资源 | 怎么获得 | 怎么花 | 代价（只属于自己） |
|---|---|---|---|---|
| 🧬 海克斯 | 算力 HE | 每月回充 4 + 每解锁一枚成就 +8 + 氪命兑换 | 8 种规则类外挂（重掷 / 概率倾斜 / 快进 / 回溯 / 义体 / 死亡豁免 / 神经加速 / 无冷却） | 健康 / 免疫 / 心情换算力；冷却与终身次数；结算按 `spent / 600` 折损（下限 0.4） |
| 💰 神壕 | 现金 + 月额度 | 不需要额外获取钱，系统直接在额度内打款 | 提款 / 钞能力兑换（贵宾医疗、私教、饭局、名师）/ 一次性清债 | 月额度 + 每月二次起边际递减 ×0.6 + 性格漂移 + 延时"树大招风"；结算按 `injected / 5000` 折损（下限 0.5） |
| 📊 人数数据化 | 观测点 DP + 人情 favor | 每月回充 3 DP；结交 / 成家 / 添丁各 +1~2 | 读取 / 拉近 / 支取人情 / 割席 / 改写标签 / 全图雷达 | DP 与人情成本；真诚度低的人会掉链子；亲情关系不可割席；结算按 `dpSpent / 400` 折损（下限 0.6） |

### 5.3 独立性是怎么保证的

| 手段 | 说明 |
|---|---|
| 运行时守卫 | 引擎侧每一处跨界调用都写成 `Game.x && Game.x.fn()`，模块脚本缺失即自动短路 |
| 零副作用attach | 数据化 `attach()` 在模块关闭时直接 `return`，**不消耗随机数、不写任何字段** |
| 随机流不污染 | 概率倾斜到期或模块重置时 `util.setLuckMul(1)` 复位，同种子仍可复现 |
| 失败即回滚 | `hex.cast` 退还 HE、`datalize.cast` 退还 DP、`tycoon.clearDebt` 退还手续费 |
| 结算层分读 | `score.js` 只是**分别**读三个 `rebate()`，高分榜 `mods` 字段只标注、不分榜 |
| 测试兜底 | `isolation.test.js` 把"互不引用 / 删脚本仍可跑 / 全关 ≡ 无模块（逐位一致）"钉成断言 |

### 5.4 纯净性

作弊局照常解锁普通成就（不额外惩罚），但**纯净向徽章要求三个标记全为 false**：

| 徽章 | 条件 |
|---|---|
| 🪶 凭自己 | 三个 `used_*` 全 false，且活到 60 岁以上安然离世 |
| 🕯️ 素手而为 | 三个 `used_*` 全 false，且净资产峰值 ≥ 100 万 |
| 🧱 白手起家 | 出身贫寒 + 净资产峰值 ≥ 100 万 + 三个 `used_*` 全 false |

与之对应，每个模块有自己的"使用痕迹"徽章（`hex_initiate` / `tycoon_initiate` /
`datalize_initiate`）、重度使用徽章（🧬 逆天改命 300 HE、💰 挥金如土 2000 万、
📊 八面玲珑 200 DP）与 🎭 三扇门（三个模块同局各用过至少一次）。

### 5.5 自动暂停（参与感）

纯快进会让人"没参与感"。控制栏里有一枚 **⏸ 自动暂停** 开关（默认开）：

- 开启后，主循环在**每年交界（生日 / 新年）**与**每次事件弹出**时自动把游戏置为暂停态，
  并弹出一个轻提示告诉你"为什么停了下来"，让你有时间停留、阅读、做选择。
- 仅在"自动播放"时生效；**手动单步**与**测试驱动**不受影响，不会把暂停的游戏"自动开始"。
- 想一路快进就再点一下开关切到 **▶ 连续播放**（仅 `config.time.autoPause` 与运行时开关两层控制）。

### 5.6 读档 · 自动续上（开箱即用）

「读档」现在**开箱即用**，不必先记得手动存档：

- **自动续档**：关闭 / 刷新页面（关页兜底）、每跨一个游戏年度、读档后，引擎都会把"进行中"的人生写进一个独立的「自动续档」槽；
- **开局自动续上**：重新打开游戏时，若检测到上次有未完成的人生，会**自动续上**并提示"已自动续上上次的人生"，点「开始一生」继续；
  若是从未玩过 / 已重开新局 / 上一局已离世，则正常开新局；
- **面板入口**：顶栏 **📂 存档** 打开面板，除 3 个手动槽位外，还会单独显示一行「自动续档」，**一键读回**；
- **金手指随档还原**：自动续档同样保存并还原海克斯 / 神壕 / 人数数据化三个模块各自的开关与账（正交性不被破坏）。

> 设计要点：自动续档只覆盖"进行中"的进度（tick>0 且存活），刚开局的第 0 帧与已离世的人生不会写入，
> 避免覆盖你上一次有效的存档；新开一局（重开）会自动清掉旧的自动续档。

## 六、事件流说明

一次典型推进（以"月"为单位）的完整链路：

```text
loop.step()
  └─ clock 推进日期 → emit('day') / emit('month') / emit('season') / emit('year')
       ├─ 月事件：consequences 兑现到期的伏笔回响
       │            actions 递减冷却
       │            decisions 按节奏抽取抉择（命中 → emit('decision:ask')）
       ├─ 季事件：weather 换季 → emit('weather:change') → disease 调整感染因子
       └─ 年事件：personality 向本性回弹、mental 结算、disease 年度风险、
                  education 升学、career 加薪晋升、invest 行情演化、
                  marriage 求偶/生育、assets 房贷扣款与折旧、
                  story 故事线进度、history 年度曲线、achievements 年度评估
  └─ hud 按 ~20fps 重绘（不参与逻辑）
```

三个关键交互回路：

1. **抉择回路**：`decisions` 触发 `decision:ask` → `hud` 弹窗 + `loop` 冻结 →
   玩家选择 → `decision:answered` → `applyEffects` 结算 → 埋种子 / 登记故事线 → 解冻推进。
2. **行动回路**：玩家点击行动 → `actions` 校验冷却与门槛 → `applyEffects` 即时生效 →
   `action:done` → `consequences` 埋种子、`story` 累积五维、`hud` 刷新。
3. **因果回路**：`plants` 写入 `seeds` → 若干月后 `timers` 到期入就绪队列 →
   后续抉择以 `requiresSeed` / `consumesSeed` 回收 → 形成"伏笔 → 回响 → 收束"的叙事链。

典型时序片段：

```text
age 26 · 买房抉择
  decisions → decision:ask('buying_home')            # 主循环冻结
  hud 弹窗：全款 / 按揭 / 放弃（含风险徽章与门槛）
  玩家选「按揭」 → decision:answered
  assets：扣首付 → 写入 mortgage 月供 → emit('asset:bought')
  story：登记「财富」故事线，注入伏笔种子 'debt_habit'
  history / achievements / hud 各自响应后 → 主循环解冻
```

## 八、贡献规范

### 7.1 红线（违反即不予合入）

1. **零外部依赖**：不引入任何第三方库、CDN、外链字体或图片，`index.html` 不得出现
   `http(s)://` 资源引用。
2. **`file://` 必须可运行**：所有功能需在双击打开的前提下可用（PWA 离线缓存等受
   浏览器策略限制的能力允许降级）。
3. **脚本加载顺序固定**：`ns → bus → util → config → state → system → loop → systems → ui → main`，
   新增文件须插入 `index.html` 对应位置（测试会校验顺序）。
4. **不改动他人字段**：各系统在 `state:reset` 中初始化自己的字段，不得直接改写 `state.js` 结构。
5. **不破坏存档兼容**：新增字段需对旧存档缺省值容错。
6. **随机数走种子 RNG**：统一使用 `core/util.js` 的种子随机，禁止直接使用 `Math.random()`，
   以保证同一随机种子的人生可复现、测试可稳定断言。
7. **金手指模块不得互串**：任一模块源码里禁止出现 `Game.xxx`（另外两个模块）的引用，
   引擎侧跨模块调用必须走守卫；新增第三/__第四个同类模块时，先补一组隔离用例。

### 7.2 新增一个系统

```javascript
/* js/systems/example.js */
```

### v1.6.2 变更一览（相对 v1.6.1）—— 单屏布局 · 矮屏修复 + 铺砖重做

- **背景**：v1.6.1 引入「单屏布局」（`js/ui/layout.js` + CSS 密度梯度），让主界面在桌面尺寸下不用滚动。
  v1.6.2 先修掉两处结构性缺陷，随后又按用户实测反馈**重做铺砖的宽高策略**（见「v2 重做」）。

**第一轮修复（结构性 bug）**

- **① 铺砖终档（`.fit-tile-2`）缺核心布局规则**：铺砖的 81 条核心规则只写了 `.fit-tile.screen-fit`，
  而脚本在矮屏（1366×768 / 1280×800）挂的是 **`fit-tile-2`** —— 两者是不同的 class，
  于是 `#app` 仍是 `column`、栅格仍是 3 列，**"零滚动"只是三列把卡片压扁的假象**（`cardSum` 1809px 被塞进 298px）。
  修法：把 81 条选择器统一改成 `:is(.fit-tile,.fit-tile-2).screen-fit`，让两档共用铺砖布局。
- **② 矮屏列宽过宽导致行高被撑高**：6 列时每列仅 ~216px，卡片内文本换行多，行高被撑到 160px+。
  修法：收窄列宽下限 —— 1366×768 由 6 列变 8 列，阵列由 4 行降为 **3 行**。

**v2 重做（用户实测反馈：`下方有部分未利用，卡片太小影响阅读`）**

第一轮的思路是「压宽度凑零滚动」，副作用是 `max-height` 被压得极狠 + 列宽只剩 190px：
1920×1080 下 8 列 × 215px，卡片换行严重、被硬截断，而阵列只占 340px、下方留白近半屏。
v2 把优先级**反转过来**：**先保可读宽度 → 再用满高度 → 最后才限高**。

- **③ 铺满高度三件套**（`.grid` 规则）：
  1. 栅格容器由 `height: auto` 改为 **`height: var(--fit-h)`** —— 必须是**确定高度**而非 `max-height`，
     否则没有"余量"可分配给行，`align-content: stretch` 形同虚设（这正是下半屏空白的根因）；
  2. **`grid-auto-rows: min-content`** —— 行高按内容。**不能用 `1fr`**，`1fr` 会在内容超出时按比例放大行高、把溢出放大；
  3. **`align-content: stretch` + `align-items: stretch`** —— 内容少时行被拉伸铺满（消除底部留白），
     内容多时行高就是内容自然高度。
- **④ 列宽下限回到可读尺寸**：宽屏 `minmax(240px, 1fr)`（1920 下 8 列 → **7 列**，卡片明显变宽）；
  矮屏 `minmax(170px, 1fr)`（必须多列才能少行；1366×768 实测 170px 排 7 列、行数 4→3 的平衡点）。
- **⑤ 矮屏统一行高**：`.fit-tile-2` 用 **`grid-auto-rows: minmax(120px, 1fr)`** ——
  内容多寡不一的卡片若各自定高，会出现"一行 157 / 一行 193"的参差、总高不可控；等高行让总额稳定塞进窗口。
- **⑥ 拆除卡片级硬截断**：删掉 `.card { max-height: 128px }` 与 `.card-log { max-height: 120px }`；
  列表型滚动区限高由 **76px 放宽到 120px**（内容不再被裁，列表能露多行）。
- **⑦ 卡内余高分配**：行被 stretch 拉高时，`.grid > section > .card { justify-content: flex-start }`
  （内容靠上、余量留底部，比上下顶开更自然，避免稀疏卡中间出空洞）；
  列表/日志类分区（`.log` / `.trait-list` / `.friend-list` / `.disease-list` / `#assetList` / `#invList` /
  `.parent-rows` / `.story-lines`）设 `flex: 1 1 auto` 吸收余高。
- **⑧ `max-height: none` 只在矮屏解掉**：宽屏行高按 `min-content`，若列表不限高会把行撑高、挤爆阵列；
  故该规则严格限定在 `.fit-tile-2.screen-fit` 前缀下，宽屏保留 `max-height: 120px`。

- **实测结果**（Edge 真机 1920×1080 全屏 / headless + CDP 实测 DOM，非估算）：

  | 分辨率 | 档位 | 列数 | 栅格 内容/容器 | 卡片高 | 整页滚动 |
  |--------|------|------|----------------|--------|----------|
  | 1920×1080 | fit-tile | 7 | **753 / 753** ✅ | 185~206 | 0 |
  | 1600×900 | fit-tile-2 | 8 | **579 / 579** ✅ | 189 均匀 | 0 |
  | 1440×900 | fit-tile-2 | 8 | **579 / 579** ✅ | 189 均匀 | 0 |
  | 1366×768 | fit-tile-2 | 7 | **447 / 447** ✅ | 145 均匀 | 0 |
  | 1280×800 | fit-tile-2 | 7 | **479 / 479** ✅ | 156 均匀 | 0 |

  **栅格内容高 == 容器高**意味着阵列真正吃满主区，下方无任何留白。
- **中年（40 岁）满内容场景复验**：`fit=true`、栅格完全铺满、`page=0`，**内容增长后布局仍稳定**。
- **小屏无损回退**：1000×700 / 900×640 / 390×844 全部 `isOn()=false`、`cls=""`、`appMaxW` 回到原始 `1180px`，
  回到自然滚动 —— 零移动端回归。
- **测试**：246/246 全绿（纯表现层改动，不影响逻辑）。
